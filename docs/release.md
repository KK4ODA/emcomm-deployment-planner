# Releases: versioning, desktop build, CI/CD, updater, code signing

## Versioning

- Semantic versioning `MAJOR.MINOR.PATCH`; pre-releases as `1.1.0-beta.1`.
- **`package.json` is the single source of truth.** `src-tauri/tauri.conf.json`
  reads it (`"version": "../package.json"`), Vite injects it as
  `import.meta.env.VITE_APP_VERSION` (shown in the sidebar and on the profile
  page), the installer file names use it, and the release workflow refuses to
  run if the Git tag does not match it.
- Git tags are `v<version>`.

## Release procedure

1. Merge everything into `main`; CI must be green.
2. Move the `[Unreleased]` notes in `CHANGELOG.md` under a new
   `## [x.y.z] - YYYY-MM-DD` heading and commit.
3. Bump and tag in one step (creates the commit `chore(release): vX.Y.Z` and the tag):

   ```bash
   npm run release:patch    # or release:minor / release:major
   git push --follow-tags
   ```

4. GitHub Actions `Release` runs (about 10 minutes):
   - `verify`: tag = package.json version, secrets present, lint/typecheck/tests
   - `web`: `dist/` zipped with a SHA-256 file
   - `windows`: Tauri build on `windows-latest`; NSIS installer + `.sig`,
     portable exe, `SHA256SUMS.txt`
   - `publish`: writes `latest.json` (updater manifest) and creates the GitHub
     Release with the CHANGELOG section as notes
5. Installed desktop apps discover the release on their next launch.

To deploy the web build, upload the contents of the release zip (or `dist/`
from `npm run build`) to the static host. `public/.htaccess` provides the SPA
rewrite for Apache.

## GitHub repository configuration

Settings › Secrets and variables › Actions:

| Secret | Required | Purpose |
|--------|----------|---------|
| `VITE_SUPABASE_URL` | yes | Baked into release builds |
| `VITE_SUPABASE_ANON_KEY` | yes | Baked into release builds |
| `TAURI_SIGNING_PRIVATE_KEY` | yes | Contents of the updater private key file (see below) |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | if the key has one | Key password |
| `WINDOWS_CERTIFICATE` | optional | Base64 of a `.pfx` code-signing certificate |
| `WINDOWS_CERTIFICATE_PASSWORD` | with the above | Certificate password |

`GITHUB_TOKEN` is provided automatically; the workflow has `contents: write`.

## Desktop build (Tauri 2)

Why Tauri rather than Electron for this app:

| | Tauri 2 | Electron |
|-|---------|----------|
| Installer size | ~5–10 MB (uses the system WebView2) | 80–120 MB (bundles Chromium) |
| Memory | one WebView2 process | Chromium + Node processes |
| Fit with React/Vite/Supabase | wraps `dist/` unchanged; no Node in the renderer needed | same UI, but tempting to move logic into Node |
| Updater | built-in plugin with mandatory signature verification, GitHub Releases manifest | `electron-updater` (mature, also signs) |
| Security | Rust host, capability allow-list per window, CSP | large attack surface, must disable Node integration |
| Toolchain | Rust + MSVC Build Tools; slower first compile | Node only |
| Maintenance | fewer dependencies to patch | frequent Chromium security releases |

The extra Rust toolchain is the only real cost, and CI absorbs it. The React
app stays the single application layer; the shell is ~30 lines of Rust.

Local build:

```bash
npm run desktop:build
# → src-tauri/target/release/bundle/nsis/EmComm Planner_<version>_x64-setup.exe
# → src-tauri/target/release/emcomm-planner.exe (portable)
```

Installer facts: per-user install (no admin prompt), Start Menu folder
"EmComm Planner", uninstaller registered in Apps & Features, WebView2
bootstrapper downloaded silently only if the runtime is missing. Metadata
(publisher KK4ODA, description, icon) comes from `src-tauri/tauri.conf.json`.

## Auto-updater

- Plugin: `@tauri-apps/plugin-updater`. Endpoint:
  `https://github.com/KK4ODA/emcomm-deployment-planner/releases/latest/download/latest.json`
  (always the newest **non-pre-release** GitHub Release, so beta tags do not
  reach stable users).
- `latest.json` is generated by the `publish` job and contains the version,
  notes, and for `windows-x86_64` the installer URL and its minisign signature.
- Client behaviour (`src/features/desktop/DesktopUpdater.jsx`): check 8 s
  after launch and every 4 h; compare versions semantically (the plugin only
  offers strictly newer versions, so downgrades and loops cannot happen); show a
  banner with release notes; **Install update** downloads with progress,
  verifies the signature against the public key compiled into the app, runs
  the NSIS installer in passive mode, then offers **Restart now**; **Later**
  snoozes that version for 24 h. Network failures are logged and retried
  silently.
- Channels: today only `latest`. To add a beta channel later, publish
  pre-release tags (already supported by the workflow), add a second manifest
  (e.g. `beta.json`) in the publish job, and let the client choose the
  endpoint from a stored preference (`check({ ... })` accepts endpoints).

### Updater signing key (required)

The key pair was generated on 2026-09-06 with `npx tauri signer generate`.

- Public key: embedded in `src-tauri/tauri.conf.json` (`plugins.updater.pubkey`).
- Private key: `C:\Users\<you>\.tauri\emcomm-planner.key` on the development
  PC. **It is not in the repository and must never be committed.** Back it up
  somewhere safe; if it is lost, installed apps can never accept another update
  and a new key must be shipped through a manually installed release.
- Put the file contents into the `TAURI_SIGNING_PRIVATE_KEY` secret. To sign
  locally instead: `set TAURI_SIGNING_PRIVATE_KEY_PATH=%USERPROFILE%\.tauri\emcomm-planner.key`.

## Code signing (Authenticode)

Builds are currently **unsigned**. Consequences: Windows SmartScreen shows
"Windows protected your PC" on first run of the installer until the user clicks
*More info › Run anyway*; some corporate machines block unsigned installers;
browsers may flag the download. Updates still work because the updater trusts
the minisign signature, not Authenticode.

To sign, obtain a code-signing certificate:

- **OV certificate** (DigiCert, Sectigo, SSL.com; ~US$200–400/year, delivered on
  a hardware token or cloud HSM since 2023). SmartScreen reputation builds up
  over downloads.
- **EV certificate** (~US$300–600/year) gives immediate SmartScreen reputation.
- **Azure Trusted Signing** (pay-as-you-go, US-based individuals/orgs with 3+
  years of history) is the cheapest cloud option; Tauri supports it through a
  custom `signCommand`.

For a `.pfx` you can export (older OV certificates or a test certificate):
base64-encode it (`[Convert]::ToBase64String([IO.File]::ReadAllBytes('cert.pfx'))`)
into `WINDOWS_CERTIFICATE` and set `WINDOWS_CERTIFICATE_PASSWORD`. The
`windows` job imports it and injects the thumbprint into `tauri.conf.json`
before building; the installer and exe are then signed and timestamped
(`http://timestamp.digicert.com`). For token/HSM-based certificates set
`bundle.windows.signCommand` in `tauri.conf.json` to the vendor's signing
command instead (see the Tauri docs on Windows code signing) and provide its
credentials as secrets. Nothing about signing is stored in the repository.

## Verifying a release manually

```bash
gh release download v1.0.0 -p 'SHA256SUMS.txt' -p '*-setup.exe'
sha256sum -c SHA256SUMS.txt
```

Install the previous version, then publish a new tag and confirm the app offers
the update within a few seconds of launch (or after clicking the version in the
sidebar footer on a future build).
